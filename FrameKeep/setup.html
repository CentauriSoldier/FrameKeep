FrameKeep setup guide

A local video library with tags, playlists, and saved playback. Your videos stay in their existing folders.

RequirementsWindowsSynologyVideo foldersThumbnailsFirst launchTroubleshooting

1. What you need

  • A PHP web server. Development has been tested with PHP 8.3 on Windows through Laragon.
  • PHP’s PDO SQLite driver (pdo_sqlite). FrameKeep creates and updates its SQLite schema automatically.
  • A writable data folder inside the application. The database, generated thumbnails, scan status, and recovery backups live there.
  • Readable video folders accessible to the account running PHP.
  • FFmpeg and PHP’s proc_open function for thumbnail generation. Without working thumbnail generation, previews may show placeholders.

FrameKeep is intended for a trusted local network. It has no user login. Permanent video deletion needs write permission to the video folder; playback and scanning need read access.

2. Run on Windows

  1. Choose the application folder containing index.php, php, includes, assets, and data. In this repository, that is the inner FrameKeep folder.
  2. Set Laragon’s document root to that application folder and start its web server. Open http://localhost/.
  3. Enable pdo_sqlite in the PHP configuration used by the web server, then restart the server if you changed it.
  4. Edit php/config.php: set D_VIDEOS to your initial library folder and F_FFMPEG to your FFmpeg executable. The checked-in paths are specific to the original development computer.

Alternatively, from the application folder, PHP’s built-in development server can provide a local preview:

php -S 127.0.0.1:8080 -t .

Then open http://127.0.0.1:8080/. This development server handles requests sequentially, so long scans or thumbnail requests can delay other requests and live status updates. Laragon is a better fit for regular use.

Mapped drive letters may be unavailable to an elevated process or service. A network share path is often more dependable; the PHP process still needs credentials and permissions.

3. Run on a Synology NAS

  1. Configure Web Station with PHP and PDO SQLite enabled.
  2. Set the site’s document root directly to the application folder containing index.php.
  3. Make data writable by the web service, and grant the web service read access to each video location.
  4. Use NAS filesystem paths in configuration and library locations, rather than Windows drive letters. For example, a shared video folder may resemble /volume1/videos; check your actual folder’s properties.
  5. Configure an available FFmpeg executable on the NAS if you want generated previews.

Use the NAS address and configured website port to open the site. localhost refers to the computer where the browser is running. A name-based portal also needs that hostname to resolve to the NAS.

Windows and NAS paths are different. Review library locations after moving a database between hosts.

4. Connect your video folders

The configured D_VIDEOS folder becomes the initial Primary library when the database is created. After that, manage locations in Settings → Libraries; changing the constant does not replace existing database locations.

Add a library name and its full folder path. Type the path manually or use Browse to choose a folder visible to the PHP host, then click Add library. Scanning searches subfolders recursively. Folder names do not assign genres or tags.

An inaccessible location is marked offline and its records are protected. Successfully scanned locations can identify missing files. Disabling a location preserves its records. Remove library — keep files removes that location’s records and playlist memberships, including video-specific tag assignments and edited names, while retaining disk files, global tags, playlists, and settings.

5. Configure thumbnails

Set F_FFMPEG in php/config.php to the executable installed on your host. PHP must be allowed to start that executable.

In Settings, choose a thumbnail size and a global Thumbnail time (seconds). The default is 10 seconds; the allowed range is 0–86400. A shorter clip falls back to its first frame if the requested position yields no image.

Previews are generated as needed and stored together in data/thumbnails. Changing the time creates new previews as they are viewed. Clear thumbnail cache removes generated images only; it does not change videos or library metadata.

6. First launch and everyday use

  1. Open FrameKeep and let its initial scan finish, or click Rescan. System messages show activity; thumbnail counts indicate what is ready or pending.
  2. Click a thumbnail or title to play. The optional scroll-to-player setting is enabled by default.
  3. Create tags and check them beneath the main player. Videos with no tags show Untagged. Sidebar sliders include, exclude, or ignore tags.
  4. Create playlists and add selected videos. Playlist organization changes database references, not file locations.
  5. Review Settings for startup scanning, periodic scanning, playback, and thumbnails. Options save automatically; new library names and paths require Add library.
  6. Use the question-mark button for the full searchable usage guide.

Playback position, volume, and mute state are stored by the site. To resume from another computer, open the same running host’s site. Browser autoplay policies may require pressing Play.

Download database backups before major reorganizations. They contain metadata, not videos or thumbnails. Restoring replaces current metadata and creates a recovery snapshot first. Keep separate backups of your video files.

7. If something does not work

  • PHP or database error: inspect the web server’s PHP error log, verify PDO SQLite, and check write permissions on data.
  • Library offline: check the exact host filesystem path, drive connection, network credentials, and PHP account’s read access.
  • No thumbnails: check FFmpeg’s path, proc_open availability, and data folder permissions. Some files may not decode successfully.
  • Video will not play: inspect FrameKeep’s media warning. Container extensions do not guarantee browser codec support. Try another known-working video to isolate a file-specific problem.
  • Autoplay stays paused: press Play or allow autoplay in your browser’s site settings.
  • Another computer cannot connect: use the hosting computer’s network address, check the server’s listening address and local firewall, and verify the correct website port.

The video card’s Delete action permanently removes files from disk after confirmation. Removing a library or a missing database record has a different scope and preserves disk files.
